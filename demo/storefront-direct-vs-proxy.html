The five GraphQL paths.

① Direct → Storefront API: the browser calls Shopify's Storefront API with the public, read-only Storefront token. Shopify serves it with access-control-allow-origin: *. No server of yours involved — the fast path.

② Gateway — dreamzapps (/graphql): your app's lean direct route on the dreamzapps.com host (behind Cloudflare, origin in the US). Calls the Storefront API server-side (public token from env) with no App Proxy HMAC and no per-request DB lookup, CORS-open.

③ Gateway — Vercel (/graphql): the same route, same code, deployed on Vercel. Its x-vercel-id reads bom1::iad1 — traffic enters at Mumbai but the function executes in US-East (iad1), so it's also US-hosted. Compare ② and ③ to isolate hosting/cold-start from code: the route is identical, so any gap is the platform, not your logic.

④ Unused in this app (no Shopify App Proxy). Direct Shopify is optional (shop + public token).

⑤ Gateway GET — appbuilder (?sha256=…): cacheable GET + persisted-query hash of the query in this file. Until the hash is registered, the lane may show PersistedQueryNotFound then reg with the full query. GET and POST share Redis. Each run uses cache:"no-store" so the browser cache does not hide network time.

⑦ Native-app hash GET uses 759dff3d… (exact document from the mobile app). Cron must have stored that body; this page cannot invent it.

If a panel says "opaque / CORS blocked": POST lanes send Content-Type: text/plain to skip preflight. Direct Shopify is CORS-open with the public Storefront token.

Confirm edge with curl -sI 'https://appbuilder.dreamzapps.com/graphql?sha256=<hash>' → cf-cache-status: HIT. Browsers often cannot read cf-cache-status cross-origin.

Token note. Optional Direct lane uses a public Storefront access token only. Never put an Admin API token here.
